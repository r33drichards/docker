Native API and authority

The manifest bindings/inspircd.json generates registration rows, utility TypeScript declarations, and a coverage inventory:

python3 tools/generate_js_bindings.py
python3 tools/generate_js_bindings.py --check

Nineteen audited utility wrappers are implemented, covering validation, glob/CIDR matching, color processing, random values, time and timing-safe comparison. Their exact signatures and conversion limits are generated from the binding manifest in the callable reference. Inputs have strict arity/types, copied ownership, and explicit conversions. NUL is rejected for native glob/CIDR functions with NUL-terminated internals. The manifest tracks reviewed declarations, manual-wrapper candidates, exclusions, and pending mutations. It is a systematic allowlist and coverage inventory, not an automatic binding of every function in inspircd.h or the whole SDK. New bindings require explicit conversion, lifetime, effect, and authorization policy plus an implementation and tests.

The callable reference derives every signature from the checked-in declarations, including native query/command/channel/admin/timer and fetch APIs. See authority and lifecycle for initialization, deferred commit and unload rules. Core compatibility methods:

  • userById(uuid) returns an owned { id, nick, isOper } snapshot or null.
  • notice(target, text) queues a server NOTICE (maximum 400 UTF-8 bytes).
  • privmsg(target, text) queues a server PRIVMSG with identical target and authority rules.
  • fetch(url, options?) stages a bounded generic asynchronous HTTP request, returning a request token. Options support GET or POST and an optional string body. Admin callbacks only; invalid requests or full queues throw.
  • takeFetchResult(token) polls/consumes {ok, status, body, bodyBytes, error}, or null while pending. body is null for invalid UTF-8; bodyBytes preserves the exact response.
  • cancelFetch(token) cancels pending work. Native request tokens are generation-scoped, not persisted JavaScript state.
  • sqlite.open(name) opens a host-granted named SQLite database (see SQLite reference).
  • rename(targetUuid, nick) queues a validated nickname change.
  • wasm(name) returns a fresh Uint8Array of a configured asset's bytes.
  • postWebhook(name, json) stages a bounded JSON POST to an administrator-configured endpoint (admin callbacks only).
  • webhookStats() returns aggregate {pending, sent, failed, discarded} counters (admin scripts only).

Default authority="user" restricts notice/privmsg/rename targets to the triggering client. Rename runs ordinary NICK processing as that client, retaining native restrictions. Explicit authority="admin" permits messaging any existing local or remote user UUID, or existing #channel; rename directly invokes the native administrative nickname change after nickname validation. No credential, operator identity, or permission is granted to a user. Queued operations re-resolve the original actor and target UUIDs and skip users who disconnected. Rename remains limited to local users. Channel NOTICE and PRIVMSG reach local members and are forwarded once through the network protocol. User messages choose local client delivery or remote forwarding, never both. These are trusted server-origin messages, not impersonated user commands; they do not apply ordinary user speaking restrictions. Targets are re-resolved at flush time; missing users/channels are skipped. No sender or raw-protocol parameter is exposed.

RSS uses the generic asynchronous native HTTP API. RSS/Atom parsing, subscriptions and deduplication are JavaScript application state; no feed-specific native host method or XML dependency is required.

At most 16 effects can be queued per file/event. All effects for the event are discarded on pre denial/error. Accepted IRC effects and HTTP commitments share the ordered main-loop safe-point queue after the current parser stack unwinds. A self-unload earlier in that queue prevents later fetch/webhook jobs from starting. Webhook and fetch workers still perform the I/O outside the IRC loop. Effects may still be skipped/rejected by native checks; queuing is not a success receipt or an atomic transaction, and a later core command rejection does not retract accepted queued effects. Native effects and commands they synchronously trigger do not invoke JS hooks, avoiding unbounded feedback loops; ordinary core/native-module checks still apply.

Opt-in channel join webhooks

Use one successful join observer, postJoin, not both userJoin and postJoin. Its arguments are event.memb.user and event.memb.channel (not event.details.memb); user.id is a plain UUID string, while nick/channel names use HookText snapshots. Copy examples/javascript/join-webhook.js into your config directory, edit its explicit channel allowlist, and load it once:

<module name="javascript">
<javascriptwebhook name="joins" url="https://hooks.example.invalid/irc">
<javascript file="scripts/join-webhook.js" authority="admin">

The URL is a placeholder: configure your own receiver and consented channels. No endpoint, script or network worker is enabled by default. The example selects local, non-quitting users to avoid reposting remote joins on every linked server, skips invalid/truncated text, and includes only an event name, user UUID/nick and channel. It does not export IP addresses, hosts, credentials or message bodies. Channel allowlist matching uses the server snapshot's exact canonical spelling. Each genuine later rejoin is a new event; this is not an exactly-once audit feed. The receiver must accept this JSON schema; services with a different schema need an administrator-authored payload adapter.

Only trusted admin-authority callbacks may call ircd.postWebhook('joins', JSON.stringify(object)). Scripts choose a configured name, never a URL, headers, method, file or credentials. Names are unique, case-sensitive ASCII letters/digits/underscore/hyphen, 1–64 characters; at most 16 endpoints may be configured. URLs are at most 2048 bytes and require HTTPS, with no userinfo, fragment, spaces or control bytes. Credentials in a private URL must remain in private server configuration. Neither URLs nor request/response bodies are logged. For isolated tests or an explicitly trusted same-host relay only, an endpoint may set loopbackhttp="yes" to allow HTTP at literal 127.0.0.1 or [::1]; hostnames and non-loopback HTTP remain rejected. HTTPS still verifies peer and hostname with the system CA trust store. Redirects, environment proxies and application retries are disabled; no cookie jar or caller-supplied auth is used.

Endpoint-specific authentication headers

An administrator can attach headers to one named destination, with values read from local secret files when configuration is loaded:

<javascriptwebhook name="nocodb" url="https://nocodb.example.invalid/api/v2/tables/TABLE_ID/records">
<javascriptwebhookheader endpoint="nocodb" name="xc-token" valuefile="/run/secrets/nocodb-token">

For Railway environments without secret-file mounts, the image provides a separately opt-in token-file startup helper using /inspircd/.secrets/nocodb-token. It does not enable forwarding by itself.

The example is disabled unless explicitly configured. Use the API route and column names required by your NocoDB installation; the join example's nested payload is not automatically a NocoDB row. An administrator-authored script can post a matching row object with ircd.postWebhook('nocodb', JSON.stringify(row)). For bearer authentication, configure name="Authorization" and put the complete Bearer ... value in its file. Never place credentials in scripts or URLs.

Files must be absolute paths, regular files owned by the daemon's effective UID, with exactly mode 0400 or 0600. All path components must be real directories or files, without symlinks, . or ..; mount secrets accordingly. Parent directories must be owned by root or the daemon and not group/world-writable. A root-owned sticky shared ancestor (such as /tmp) is accepted only when immediately followed by a daemon-owned 0700 directory. Values are read verbatim: 1–1024 bytes, no NUL, CR, LF, tab, other ASCII control bytes or DEL. In particular, do not end a token file with a newline. No trimming or interpolation occurs. Missing, unreadable, changed-during-read, unsafe or invalid files reject the whole candidate configuration, retaining the last-good generation on rehash.

The directive is repeatable: maximum 8 headers per endpoint, 64-byte HTTP token names, and 8192 aggregate header bytes including names, values and : / CRLF. Names are case-insensitive; duplicates and unknown endpoints are errors. Transport/control fields cannot be overridden: Host, Content-Type/Length/Encoding, Transfer-Encoding, Accept-Encoding, Expect, Connection, Keep-Alive, TE, Trailer, Upgrade, HTTP2-Settings, Cookie, Set-Cookie, proxy-* and method-override variants. Headers belong only to their configured endpoint. Redirects remain disabled.

Scripts cannot set/read headers or open the files. Secret values and file paths are omitted from loader diagnostics, logs, counters and the JavaScript API. Immutable header storage is shared by the owning generation and its requests; editing a file has no effect until a successful rehash. Rotation retires old queued work and cancels old in-flight work under the same rules below; already transmitted requests cannot be recalled. Secrets remain in process/libcurl memory while owned; this does not guarantee zeroization or protection against process memory access. This change supplies authentication only, with no new event hooks, durable delivery, automatic retries or default credentials.

The payload must be a UTF-8 JSON object string, at most 16 KiB. Invalid arity, types, JSON, destinations, excessive per-event effects, initialization calls and user-authority calls are script errors under the existing failure policy. true means staged, not sent: every request shares the event's 16-effect budget and is discarded with the entire batch on denial, exception, timeout or unsupported Promise return. A full queue returns false without blocking or retrying. As with other effects, a later native veto cannot undo an already accepted batch: use a successful observer such as postJoin for join receipts.

One worker owns copied requests; it never enters V8 or accesses native IRC objects. A module-wide maximum of 64 reservations covers staged, queued and in-flight payloads across all scripts/generations. Transfers have 1-second connect and 2-second total libcurl timeouts and discard at most 64 KiB of combined response headers/body. Curl must support thread-safe global initialization and asynchronous DNS; native build requires libcurl 7.85+ development headers, runtime library and CA certificates. Deadlines are not a hard real-time scheduling guarantee.

A failed rehash retains the old generation and configured destinations, and candidate initialization cannot send. A successful rehash retires old queued jobs and requests cancellation of old in-flight transfers without retargeting them. Unload clears queued work, requests cancellation, and joins the owned worker. A request already transmitted cannot be recalled. There is no persistence or automatic retry: timeout/cancellation/crash outcomes can be ambiguous, and HTTP 2xx means only that the receiver accepted the HTTP request, not that downstream actions completed. Consumers needing delivery/idempotency must implement their own stable event IDs, durable receiver and reconciliation.

webhookStats() reports reservations still alive (pending), completed 2xx responses (sent), failed/ambiguous transfer attempts (failed), and queued jobs discarded before an attempt (discarded). Pre-batch aborts simply release their reservations. Counters reset on module unload, not rehash; no endpoint, credential, body or response is exposed.

Local checks: node tests/test_join_webhook.cjs and python3 tests/test_js_webhooks.py (C++17 compiler, pkg-config/libcurl, OpenSSL CLI and Python required; no dependency-skip fallback). The latter creates only owned loopback HTTP/TLS fixtures and checks bounds, cancellation, no redirects, proxy suppression, untrusted certificate rejection and HTTP error/size/timeout handling. The native daemon suite additionally exercises real JOIN-to-POST, rejoin, authority, rollback and failed-rehash behavior.

URL-scoped fetch headers

Host configuration can inject headers into ircd.fetch without exposing a credential getter or accepting JavaScript-supplied headers:

<javascriptfetchheader script="scripts/trusted.js" url="https://api.example.invalid/v1/events?scope=irc" name="Authorization" valuefile="/run/secrets/api-header">

script resolves relative to the configuration directory (or may be absolute) and must identify a loaded admin-authority source after canonicalization. Rules match that source and the complete parsed URL, not a substring or prefix. Scheme/host case and an explicit default port are normalized. Path and query bytes, case, and ordering must match exactly, including a trailing empty ?. Userinfo, fragments, backslashes, and literal ./.. path segments are rejected. Only HTTPS URLs accepted by the ordinary fetch policy may have rules; injection does not relax its public-address, standard-port, no-proxy or no-redirect policy.

There are at most 32 distinct source/URL rules and eight headers per rule, using the same header-name, secret-file ownership/mode, value and byte limits as javascriptwebhookheader. Config loading is atomic. Duplicate headers or conflicts with legacy endpoint headers reject the candidate configuration. Header values stay in native state and are not exposed by an API or logged. However, fetch returns the remote response: configure only trusted endpoints that will not reflect credentials. Host injection cannot prevent a recipient from returning or encoding a received secret.

postWebhook remains a compatibility adapter over the same asynchronous HTTP implementation. Named endpoint configuration, JSON POSTs, private/explicit loopback endpoint authority, one-worker ordering, 64-job bound, timeouts, response-discarding and counters remain supported. Legacy endpoint credentials do not automatically become fetch rules. URL rules also apply to a matching named webhook from the specified script. Generic fetch still has its own per-script two-worker/16-job limit and does not inherit legacy destination exceptions. Disabling a poisoned script retires its queued/in-flight HTTP jobs; rehash/unload do the same. Already transmitted requests cannot be recalled.
