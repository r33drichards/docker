Configuration

docker build -t inspircd:local .

The primary image uses Alpine 3.22, InspIRCd v4.12.1 by default, and matching nodejs-dev/nodejs-libs 22.23.2-r0. Only V8 APIs are used; no Node environment, process, require, filesystem API, network API, or WASI is installed in scripts. The root Dockerfile includes the compiled module and its runtime library, but leaves it unloaded until explicitly configured. No scripts are installed or enabled by default. Dockerfile.javascript has been retired; downstream Railway projects can build the root Dockerfile and supply their own configuration and scripts. Existing /inspircd/conf/ volumes are preserved by the unchanged entrypoint. Update NODEJS_VERSION for both stages together for security updates. The build checks that the module links libnode and has the ELF NODELETE flag.

Example configuration (files must already exist):

<module name="javascript">
<javascriptsettings timeoutms="25">
<javascript file="scripts/hooks.js">
<javascript directory="scripts/extra" authority="user">
<javascript file="scripts/operator.js" authority="admin">
<javascriptwasm name="answer" file="scripts/answer.wasm">
<log method="stdout" level="normal" type="m_javascript">

Relative paths resolve under InspIRCd's configured config directory. Source entries execute in configuration order; direct regular .js files inside each directory execute in bytewise filename order. Subdirectories and discovered symlinks are skipped. Explicit file/directory symlinks are canonicalized. Duplicate canonical source paths, missing/unreadable files, empty matching directories, and oversized sources fail configuration. Defaults are 128 sources, 1 MiB per source, and 16 MiB total; Wasm assets have the same separate limits. Wasm asset names are unique case-sensitive ASCII letters/digits/underscore/hyphen, 1–64 characters; only explicitly configured .wasm files are loaded.

Each JavaScript file has its own isolate, global state, and configured authority. Directory authority is inherited by every discovered file. Scripts cannot select or change their authority, share globals with more privileged files, or choose a native execution actor. Scripts are loaded as classic synchronous scripts, not ES modules; no implicit imports, recursive includes, filesystem watching, or timers.

Normal InspIRCd rehash loads a complete candidate set with fresh isolates. It replaces the active set only after every file initializes successfully. A failed candidate leaves the previous scripts and their state active. Native mutations are prohibited during initialization. Filesystem reads are bounded but are not a filesystem-wide atomic snapshot. Successful reload resets all JavaScript state.
