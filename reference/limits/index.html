Execution and failure limits

Script initialization and each file's stage callback batch share its configured wall-clock deadline (default 25 ms, configurable 1–1000 ms). A joined watchdog terminates JavaScript/Wasm execution. A pre exception, timeout, invalid decision, or Promise result rejects the command and disables that file until a successful rehash. Subsequent events needing its callbacks fail closed. A failed post-only file does not block commands through an empty pre stage. Post failures discard that event's queued effects and are reported without script-controlled data. Already-committed effects from earlier events are not rolled back.

There are no automatic microtask checkpoints; asynchronous hooks, Promises, and async Wasm compilation are unsupported. Atomics.wait is disabled. Use new WebAssembly.Module(bytes) and new WebAssembly.Instance(module, imports). Synchronous Wasm compilation/calls run within the same deadline; traps are normal script errors. Each isolate has a 32 MiB old-generation target, not a hard total memory cap. ArrayBuffers/native allocations and process-wide V8 resources are outside it. Total work and memory grow with configured files. Use a small source set; a separate process would be needed for hard resource/crash containment.

V8's platform is process-lifetime and never globally disposed/reinitialized on rehash or module reload. ELF NODELETE retains callback/platform code; musl also does not unload DSOs. Per-script handles, watchdogs, contexts, and isolates are cleaned up. Reloading the same module is supported; replacing the module binary or V8 libraries requires restarting the daemon. This module assumes sole ownership of V8 initialization in the process.
