Separate event-provider hooks

These events supplement the generated core Module hooks. They register against InspIRCd 4.12.1 event providers and become active when the provider is loaded; loading JavaScript does not load services, CAP, HTTP, or spanning-tree for you. Listeners survive provider unload/reload. Callbacks are synchronous and must not return a Promise, including from an async function.

All payloads are detached, bounded copies. Assigning to them does not modify native state. Text uses HookText (text, bytes, byteLength, truncated), not a plain string. text may be null for invalid UTF-8. Each event also includes stage and userId (null when there is no acting user). No socket, response context, native object, or native pointer is exposed.

Event names and fields

Events Additional payload fields
accountChange user, account, loggedIn; empty account means logout
userPreAway user, message
userPreBack user
userAway, userBack user, previouslyAway, previousMessage, previousTime, away, message, time; times are Unix seconds
whois source, target
whoisLine source, target, numeric
whoLine source, user, membership, numeric, and WHO request fields below
whoMatch source, user, and WHO request fields
whoVisible source, membership, and WHO request fields
namesListItem issuer, membership, prefixes, nick
stats source, symbol; response rows are deliberately omitted
capAddDel name, adding
capValueChange name; values may be user-specific and are omitted
serverLink, serverBurst server fields below
serverSplit server fields and error
syncUser server fields and user
syncChannel server fields and channel
syncNetwork server fields
httpACLCheck, httpRequest method, path, address only

WHO request fields: matchText, matchChannel, fuzzyMatch, whox, queryType. Server fields: serverId, serverName, serverDescription. Server names and identifiers are text snapshots, unlike the plain-string user snapshot id.

Native decisions

  • userPreAway, userPreBack, whoLine, whoMatch, whoVisible accept {action: 'pass'}, {action: 'deny'}, or {action: 'allow'}. allow requires an administrator-authority script because it can bypass later native policy.
  • namesListItem, whoisLine, stats accept only pass or deny. For STATS, deny means "handled" and suppresses subsequent native handling; this bridge does not provide a response-row builder.
  • Other events are observers. Return values do not claim native ownership or bypass permissions. In particular HTTP events always return native passthrough. A native HTTP deny would imply that the module already answered the socket; this bridge cannot do so. HTTP bodies, headers (including Authorization and cookies), query parameters, and fragments are never copied.
  • Decision-hook failures fail closed; observer failures do not stop the native operation. Existing script quarantine and authority rules still apply.
  • CAP events concern server capability registration/value changes, not an individual client's CAP REQ state. Use validated command hooks to observe client commands; do not infer successful CAP negotiation from the request.

Account events require a provider such as services_account; away, WHO, WHOIS, NAMES and STATS use their core providers; CAP uses cap; server events use spanningtree; HTTP uses httpd. A subscription without its provider is inert, not an error.

Example: refuse one away message and count logins

// Load as a trusted script. No network calls or asynchronous callbacks.
let logins = 0;
const exactText = value => value && !value.truncated &&
  typeof value.text === 'string' ? value.text : null;

ircd.on('userPreAway', event => {
  if (exactText(event.message) === 'reserved test message')
    return {action: 'deny'};
});

ircd.on('accountChange', event => {
  if (event.loggedIn) ++logins;
});

ircd.on('serverSplit', event => {
  // Safe to retain: these objects contain copies, not live native handles.
  const name = exactText(event.serverName);
  if (name !== null) globalThis.lastObservedSplit = {name, error: event.error};
});

The counter and last split live only for this script generation; a successful rehash replaces them. Retained snapshots do not authorize any later action.

Complete TypeScript event declarations

/** Optional-provider event snapshots. Referenced by js_api.d.ts. */
interface HookAwayChange {
  user: HookUser | null; previouslyAway: boolean; previousMessage: HookText;
  previousTime: number; away: boolean; message: HookText; time: number;
}
interface HookWhoRequest {
  source: HookUser | null; matchText: HookText; matchChannel: HookChannel | null;
  fuzzyMatch: boolean; whox: boolean; queryType: HookText;
}
interface HookServerEvent {serverId: HookText; serverName: HookText; serverDescription: HookText}
interface HookHttpEvent {method: HookText; path: HookText; address: HookText}
interface ModuleHookEvents {
  accountChange: {user: HookUser | null; account: HookText; loggedIn: boolean};
  userPreAway: {user: HookUser | null; message: HookText};
  userPreBack: {user: HookUser | null};
  userAway: HookAwayChange;
  userBack: HookAwayChange;
  capAddDel: {name: HookText; adding: boolean};
  capValueChange: {name: HookText};
  namesListItem: {issuer: HookUser | null; membership: HookMembership | null; prefixes: HookText; nick: HookText};
  stats: {source: HookUser | null; symbol: HookText};
  whois: {source: HookUser | null; target: HookUser | null};
  whoisLine: {source: HookUser | null; target: HookUser | null; numeric: HookNumeric};
  whoLine: HookWhoRequest & {user: HookUser | null; membership: HookMembership | null; numeric: HookNumeric};
  whoMatch: HookWhoRequest & {user: HookUser | null};
  whoVisible: HookWhoRequest & {membership: HookMembership | null};
  serverLink: HookServerEvent;
  serverBurst: HookServerEvent;
  serverSplit: HookServerEvent & {error: boolean};
  syncUser: HookServerEvent & {user: HookUser | null};
  syncChannel: HookServerEvent & {channel: HookChannel | null};
  syncNetwork: HookServerEvent;
  httpACLCheck: HookHttpEvent;
  httpRequest: HookHttpEvent;
}
