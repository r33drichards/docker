Command hooks

See examples/javascript/hooks.js and modules/js_api.d.ts.

ircd.on('preCommand', event => {
  if (event.command === 'EXAMPLEPING')
    return { action: 'pass', command: 'PING', params: ['hello'] };
});
ircd.on('postCommand', event => {
  if (event.command === 'VERSION')
    ircd.notice(event.userId, 'Handler result: ' + event.result);
});

Register at most 16 callbacks per stage per file during initialization. Callbacks run synchronously in registration order, then file order. Pre callbacks receive owned command/parameter snapshots at validated=false. Post callbacks receive result (SUCCESS, FAILURE, INVALID) and loop, matching the native hook. validated is true for the post-handler snapshot. This does not prove delivery to another client. The earlier debug logger still observes validated pre events.

Fields are command, params, commandBytes, paramBytes, userId, stage, validated, result, and loop. Valid UTF-8 text becomes JavaScript strings; invalid UTF-8 becomes null in the corresponding text field. Uint8Array fields always preserve exact owned bytes, including invalid UTF-8. Tags, client identity fields, and native pointers are not exposed. Editing an event does not edit IRC state. Snapshot values are unredacted; scripts must handle credentials/private messages appropriately. The bridge itself does not print command contents or script exception text. The separate debug logger does print unredacted contents.

Pre return values:

  • undefined or { action: 'pass' }: continue ordinary core processing.
  • { action: 'deny' }: stop processing and discard this event's queued effects.
  • { action: 'pass', command: 'PING', params: ['text'] }: request a rewrite.

Rewrite parameters may also be Uint8Array values. Rewrites require uppercase ASCII command tokens, at most 15 parameters, a conservative 510-byte line limit, no NUL/CR/LF, and valid middle-parameter syntax. Lone UTF-16 surrogates are rejected. Unknown/server-only target handlers are rejected. Rewrites are redispatched under the original client through the core parser, including operator/registration checks, rather than invoking a cached handler. Tags are retained internally. This incurs additional core flood accounting. The exact replacement skips a second JS pre pass; nested commands still pass through hooks, with rewrite depth bounded to eight. A later script sees earlier scripts' proposed changes.

Other modules may veto before this hook, and unknown commands can reach native pre hooks more than once when another module resolves them. Core-generated commands and per-target post events may also appear. There is no exactly-once or complete-audit guarantee. Post return values are ignored except that Promises are rejected. A post error cannot undo a command that has already executed.
